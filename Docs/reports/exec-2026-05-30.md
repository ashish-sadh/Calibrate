# Drift Daily Briefing — May 30, 2026

## Headline
Voice-first exercise logging shipped; weight chart UI polish driving stronger data visualization across the app.

## Product Snapshot
Drift is an AI-first health tracker — users type or speak what they ate or did, AI handles logging, tracking, and insights. On-device, no cloud. Currently in closed beta on TestFlight.

| | |
|---|---|
| Beta Build | 286 (shipped 2026-05-30) |
| Test Suite | ~1,253 iOS DriftTests + ~1,552 DriftCoreTests; ~160+ LLM eval cases |
| AI Capabilities | 35 tools (23 core + 12 insight engines) |
| Food Database | 5,420 foods (hand-curated Indian-first + international) |

## What Shipped This Period
- **Voice/text exercise logging surface** — ExerciseVoiceLogSheet unifies voice input and manual entry for exercises; users can now log by speaking "10 squats at 185" or typing
- **Weight chart zoom & pan** — scrollable chart with range-based zoom, pan through full history, adaptive y-axis scaling for better visual clarity
- **Weight chart polish** — indigo trend line (cleaner than black), calmer palette, sparkline delta chips align with trend not endpoints, larger legend
- **Food diary fixes** — removed duplicate "Done" button in LogMealSheet; diary now refreshes after logging (was showing stale state)

## What's Working Well
- **AI chat foundation is robust** — 35 tools, 50-case gold set validates 96% per-tool reliability (log_food, log_weight, mark_supplement all at 100%)
- **Test discipline holding** — cross-platform pure-logic tests in DriftCore run warm in ~7s; iOS integration tests (HealthKit, Widget, Speech) ~25s; LLM eval ~12 min
- **UI momentum** — weight charting improvements are visually impressive and set the bar for other data entry surfaces (exercise history, meal visualization)

## Risks & Blockers
- **State.md is 52 builds behind** — says build 234, we're at 286. Stale documentation creates drift; should auto-update or deprecate
- **Voice input parity** — ExerciseVoiceLogSheet is new; need to validate edge cases (background noise, multi-rep parsing, metric units) before shipping to wider beta
- **Food database ceiling enforced but not documented** — 6,000 food cap exists in tests but rationale isn't clear to future maintainers

## Focus for Next Period
1. **Normalize voice input across all entry surfaces** — meal logging, weight, supplements should have parity with exercise voice sheet (reduces UI confusion, increases adoption)
2. **Validate AI routing on recent UI changes** — confirm ExerciseVoiceLogSheet and weight chart don't introduce new edge cases in intent classification (test with real voice samples)
3. **Update Docs/state.md or switch to auto-maintenance** — either wire build number + test counts into the doc via script, or deprecate in favor of git log + CI status
